# GHOST v0.4 Specification: In-Circuit Value Conservation

- Spec status: DRAFT - normative target for the v0.4 implementation series.
- Scope: crates/ghost-zk, crates/ghost-wallet, consensus validation, tx
  format v4.
- Baseline: v0.3.0 (first public release). Proving system: halo2_proofs
  0.3.5 with the IPA commitment scheme over the Pasta (Vesta) scalar
  field; no trusted setup.
- The key words MUST, MUST NOT, SHOULD, MAY are read as in RFC 2119.

## 1. Problem statement

v0.3.0 proves, in zero knowledge, that a spend key belongs to the global
note-commitment tree at depth 2^32 (FcmpCircuit, leaf hash
h_tree = P(D, a+b, a*b), sparse frontier, O(leaves + depth)). The
economic correctness of a transaction, however, is currently established
by ordinary consensus logic outside the proof system:

- nullifier-reuse prevention is a consensus-side seen-set check, and the
  binding between a published nullifier and the witnessed note is not a
  first-class statement of the circuit;
- the value balance (inputs cover outputs plus fee) is enforced by
  off-circuit accounting, so a validator trusts bookkeeping code rather
  than the proof itself.

The FCMP++ end-state collapses all of this into ONE proof per
transaction. v0.4 requires that a single proof establishes:

- P1 (membership): every spent note owner key is a member of the
  accumulator at the published root;
- P2 (nullifier): every published nullifier N_i is derived from the SAME
  witness as P1 (same owner key shares, same per-note rho);
- P3 (conservation): the sum of spent values equals the sum of created
  values plus the fee, every value range-checked, via value commitments
  the circuit itself constructs;
- P4 (authorization): the transaction is bound to its sighash by a
  binding signature that only the opener of all value commitments can
  produce.

Non-goals for v0.4: multi-asset transfers (asset_id is fixed to 0),
CLSAG adaptor signatures and hashlock-in-circuit (separate work item),
encrypted note transport changes, mainnet activation.

## 2. Notation and primitives

- Fq: the circuit scalar field (Pasta, Vesta lineage) used by
  halo2_proofs 0.3.5 in ghost-zk. G: the standard base point of the
  existing ghost-zk point arithmetic (the tree-add / tree-mul gates).
- Point addition and scalar multiplication follow the existing ghost-zk
  conventions; encoded points are represented in-circuit as Fq elements.
- Poseidon_3(x, y, d): the ghost-zk Poseidon permutation instance
  (t=3, x^5 S-box, 64 uniform full rounds, circ(2,1,1) MDS matrix,
  blake3-derived round constants). The third slot d carries a domain
  constant. All domain constants are blake3("GHOST/v4/dom/<name>")
  reduced into Fq and published as test vectors.
- blake3: the existing hash for transcripts, ids, and non-circuit
  derivation.
- hashgen(name) -> Point: t = blake3("GHOST/v4/gen/<name>") reduced mod
  the group order; returns the point [t]G. The discrete logarithms
  between any two hashgen outputs MUST be unknown; the derivation is
  published with test vectors (nothing-up-my-sleeve).
- Fixed generators defined by this spec:
  - V  = hashgen("value") - value generator for value commitments;
  - R  = hashgen("blind") - blinding generator for value commitments;
  - G3 = hashgen("leaf")  - value-binding term of the accumulator leaf.

## 3. Keys, notes, and the accumulator leaf

An address is (D, key shares) where D is the existing diversified base
and the owner key shares (a, b) satisfy the existing leaf relation
(a+b, a*b). The spender, and only the spender, knows (a, b).

A note (normative v0.4 preimage) is:

    note = (asset_id = 0, v, rho, D, a, b)

- v: amount, 0 <= v < 2^64, native units.
- rho: per-note nullifier seed, a fresh Fq element chosen at note
  creation (blake3-based derivation wallet-side); rho uniqueness per
  leaf is what makes nullifiers unique.
- r: value-commitment blinding, generated at spend time (Section 4);
  wallets MAY persist it for debugging but correctness does not require
  persistence.

Accumulator leaf v2 (replaces the v0.3.0 key-only leaf; activates a NEW
accumulator instance, see Section 9):

    H_leaf = Poseidon_3(v, rho, DOM_LEAF)
    L = P(D, a+b, a*b) + H_leaf * G3

where P(D, x, y) is the existing ghost-zk leaf point. The normative
requirement is linearity: L binds (D, a+b, a*b, v, rho), so a membership
proof for L attests the key AND the note seed/value term together.
Outputs publish L_j; consensus inserts L_j into the frontier.

## 4. Value commitments

For every input i and output j the transaction carries a value
commitment

    RC = v * V + r * R,   r uniform in Fq

- The circuit constructs RC itself (fixed-base gate, Section 8); the
  prover MUST NOT be able to supply RC values the circuit did not derive
  from the witnessed (v, r).
- Range check: v is decomposed into 4 limbs of 16 bits, each limb
  range-checked; the limb decomposition MUST reproduce v exactly.
- A published RC is computationally hiding (r uniform) and binding.

## 5. Nullifier

    nk = Poseidon_3(a, b, DOM_NK)       - nullifier key
    N  = Poseidon_3(nk, rho, DOM_NU)    - nullifier, public input

Requirements:

- N MUST be computed in-circuit from the SAME (a, b, rho) witnesses
  that satisfy the leaf membership statement (P2). A nullifier derived
  from a different note MUST fail verification.
- N is deterministic per note: spending the same note twice publishes
  the same N, which the consensus seen-set rejects (Section 9). The
  seen-set is defense-in-depth; the in-circuit binding is the primary
  guarantee.
- N MUST NOT reveal nk, rho, a, b, or the leaf position.

## 6. Balance and the binding signature

Homomorphic balance (checked by the verifier over public points):

    sum(RC_in) - sum(RC_out) - fee * V = O

Binding signature (Schnorr over base R, adapting the Orchard bind_sig
concept):

    bsk = sum(r_in) - sum(r_out)             (mod group order)
    bvk = sum(RC_in) - sum(RC_out) - fee * V
    bind_sig = Schnorr_sign(bsk, S, H("GHOST/v4/bind", S, bvk))

where S is the sighash (Section 7). Verification recomputes bvk from tx
data and checks the signature under public key bvk with base R.

Why it binds: with honest values, bvk = bsk * R and the signer knows
bsk. If sum(v_in) - sum(v_out) - fee = d != 0, then
bvk = d * V + bsk * R, and producing a valid signature requires the
discrete logarithm of V with respect to R - unknown by construction
(Section 2). Conservation is therefore enforced with zero trust in
off-circuit accounting.

## 7. Transaction format v4

    tx v4:
      version            u32 = 4
      acc_root           point (public accumulator root)
      inputs[]           n_in in [1, MAX_IN = 2]:
            N_i          nullifier (field element, canonical)
            RC_in_i      value commitment (point)
      outputs[]          n_out in [1, MAX_OUT = 4]:
            L_j          new accumulator leaf (point)
            RC_out_j     value commitment (point)
            enc_note_j   opaque wallet note payload (v0.3 transport
                         unchanged; dedicated encryption is a separate
                         roadmap item)
      fee                u64, native units
      proof              halo2 IPA proof
      bind_sig           64-byte Schnorr

Sighash:

    S = blake3("GHOST/v4/sighash", le64(version), acc_root,
               N_1..N_n, L_1..L_m, RC_in_1..RC_in_n,
               RC_out_1..RC_out_m, le64(fee))

Every serialized field consumed by verification MUST be covered by S.

## 8. Circuit layout

FcmpCircuit v4 keeps the single-region style of v0.3.0 (poseidon-round
with degree 5 + absorb masking, init-zero, tree-add, tree-mul) and adds:

- rc-limb gate: 4 x 16-bit limb decomposition plus running-sum range
  check for every value (input and output).
- rc-fixed-base gate: windowed fixed-base scalar multiplication
  computing RC = v * V + r * R in-circuit from the limb witnesses; the
  synthesized result is exposed as a public instance and cross-checked
  against host-side computation in tests.
- nullifier gate: nk and N from Section 5 (two Poseidon_3 permutations)
  sharing witnesses with the leaf membership path.
- leaf-v2 gate: H_leaf = Poseidon_3(v, rho, DOM_LEAF) and the G3 term
  of L.

Public instances (order normative):

    instance[0]              acc_root
    instance[1 .. n_in]      N_i
    next n_in * 2 slots      RC_in_i (encoded points)
    next n_out * 2 slots     RC_out_j

Topology: MAX_IN = 2, MAX_OUT = 4; smaller transactions are padded with
disabled rows. Phase 1 lands the wallet topology (n_in = 1, n_out = 2)
first, with the gates written generically.

Cost budget: the v0.3.0 mock is 2342 rows at k=12. The added gates are
estimated at roughly 40-70 rows per value commitment plus about 130
rows for nullifier/leaf hashing per side; the design MUST stay within
k=13 (mock-prover row counts are the Phase 1 acceptance gate). Proving
time MUST stay under 10 s for a full v4 spend at 2^32 leaves on the
v0.3.0 reference machine (baseline 2.1 s for membership only).

## 9. Consensus rules

Validation order for a v4 transaction (all steps REQUIRED, first
failure rejects):

  1. parse: structure, sizes (n_in, n_out bounds), enc_note length caps;
  2. proof: halo2 verify against public instances reconstructed from
     the serialized tx (instances MUST equal tx fields exactly);
  3. balance: sum(RC_in) - sum(RC_out) - fee * V = O;
  4. bind_sig: valid under bvk over S;
  5. nullifier seen-set: every N_i unseen (defense-in-depth, retained);
  6. leaf insertion: every L_j enters the sparse frontier; the
     resulting root MUST be the next canonical frontier root;
  7. fee floor: fee >= FEE_FLOOR (consensus parameter, testnet
     default 0).

Activation:

- CONSENSUS_V4_ACTIVATION_HEIGHT (testnet parameter). At and after the
  height, v4 is the only accepted version; v <= 3 is rejected.
- v4 activates a NEW accumulator instance (fresh sparse frontier at the
  activation height). Pre-mainnet this is a testnet reset of the
  shielded pool and is acceptable; it MUST be documented in the release
  notes.

## 10. Wallet changes (ghost-wallet)

- build_zk_spend v4: note selection (single-note selection retained for
  the first cut), change output, fee = max(FEE_FLOOR, configured fee),
  RC computation, proof, bind_sig. The existing invariant is preserved:
  prove and self-verify BEFORE any wallet state mutation.
- confirm_zk_tx mirrors the consensus order of Section 9 (the wallet is
  the first validator of its own transactions).
- The nullifier seen-set registry and tree introspection gain the
  leaf-v2 layout; TreeState.mainnet() constructs the NEW accumulator
  instance.
- WalletNote persists (v, rho, D, a, b); rho uniqueness is enforced at
  note creation.

## 11. Security considerations

- Generator derivation: all new generators come from hashgen with
  published test vectors; no trapdoor exists in V, R, G3 beyond
  discrete-log hardness. bind_sig soundness relies on dlog_R(V) being
  unknown.
- Cofactor: Pasta curves have cofactor 4; all point encodings follow
  the existing ghost-zk conventions (cofactor handling, canonical
  encoding). Verifiers MUST reject non-canonical encodings.
- Malleability: S covers every consumed field; third parties cannot
  mutate fee, RCs, leaves, or nullifiers without invalidating bind_sig.
- Replay: N is unique per note (Section 5) plus the retained seen-set.
- Inflation: conservation is proven; the remaining trust boundary is
  consensus issuance policy (the wGHOST quorum mint stays
  AUDIT REQUIRED).
- Griefing: FEE_FLOOR and enc_note length caps bound spam; per-tx
  verification cost is bounded by the fixed topology.
- An external security audit remains REQUIRED before any mainnet use.

## 12. Delta vs v0.3.0

| Area | v0.3.0 | v0.4 (this spec) |
|------|--------|------------------|
| leaf | key-only P(D, a+b, a*b) | + H_leaf * G3 value/rho binding, new accumulator instance |
| nullifier | published; reuse prevented consensus-side | N = Poseidon_3(nk, rho) proven in-circuit from the same witness as membership (P2) |
| value | off-circuit Pedersen accounting | RC built in-circuit, homomorphic balance, bind_sig (P3, P4) |
| public instances | root, nullifier | root, N_i, RC_in_i, RC_out_j |
| tx | v3 | v4 + activation height + fee floor |
| wallet | prove + self-verify before mutation | invariant unchanged, v4 fields |

If the Phase 1 code audit finds that the current single-input circuit
already derives N in-circuit, the nullifier gate work reduces to the
multi-input generalization and witness sharing; requirements P1-P4 do
not change.
